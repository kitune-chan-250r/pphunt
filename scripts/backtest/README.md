# バックテストハーネス（Phase 3 / DESIGN.md §3.6）

RecommendMap アルゴリズム v2 の time-split バックテスト。締切 T 以前のスコアだけでモデルを作り、T 以後に実際に ΔPP が増えたプレイを当てられるかを、ベースライン3種と比較する。

## 実行方法

```bash
npm run test:backtest
```

これは `BACKTEST=1 vitest run --config scripts/backtest/vitest.config.ts` の略。`backtest.test.ts` は環境変数 `BACKTEST=1` が無いと skip されるため、通常の `npm run test:unit` には影響しない。ライブ API を叩くため、テストのタイムアウトは 600 秒に設定してある。

## 何をするか

1. **サンプル選定（決定的）**: `GET /api/v2/players?sort=rank&limit=100&page=9` から、ランク 500–3000 かつ `totalPlayedRankedLeaderboards >= 80` を満たす最初のプレイヤー1名を選ぶ。**単一プレイヤーの予備サンプル**であり、DESIGN.md §3.6 の100人規模の層化評価ではない。
2. **取得**: 本人のプロフィール・top 100・recent 100、ランク ±100 のプレイヤー（総 PP 比 [0.6, 1.6] で絞り最大40人）の top 100。リクエスト間隔は約300ms、失敗時は1回だけリトライする。
3. **分割**: 締切 T = 90日前。学習集合 = T 以前の自分のスコア、テスト集合 = T 以後のスコアのうち実績の重み付き ΔPP（`ppGain.ts` の `deltaPpForScore`）が 1 以上だったもの。テスト集合が3件未満なら T を180日前にずらす。近傍のスコアも T 以前のみに絞る（anti-leakage）。
4. **候補母集団**: 近傍の学習スコアに現れる譜面 ∪ 自分の学習済み譜面。正解 gain はテスト集合に入っていればその実績 ΔPP、それ以外は 0。
5. **比較するランキング**:
   - (a) フルモデル: `accuracyCurve.ts` / `ppCurve.ts` / `similarity.ts` を使い、本体フックの簡略鏡写し（CF 輸送ブレンドは類似プレイヤー10人以上のとき、LCB は q=0.20、未プレイ譜面にはクリア可能性ゲート）。譜面残差 ε_m と MMR は省略。
   - (b) 人気順: 近傍の出現人数順（同点は競合者最高 PP）。
   - (c) フラット95%: 全候補の精度を 0.95 と仮定して ΔPP を計算し順位付け。
   - (d) 現行方式の近似: 未プレイ候補のみ、競合者最高 PP >= 本人の plusOnePP、出現人数順。
6. **指標**: NDCG@20 と Recall@20（gain = 実績 ΔPP）。結果は `results.json` と `RESULTS.md`（日本語レポート）に書き出される。

## キャッシュ

取得した API レスポンスは URL の SHA-256 ハッシュをキーに `/tmp/pphunt-backtest-cache/` へ保存され、再実行時はキャッシュから読む（ネットワークへ出ない）。キャッシュを消せば再取得になる。なおキャッシュには鮮度管理が無いため、時間を置いた再計測では先にキャッシュを消すこと。

## 注意

- API はベストスコアしか返さないため、結果には打ち切りバイアスがある（詳細は `RESULTS.md` の「既知のバイアス」）。
- ネットワークが全面的に失敗した場合は数値を捏造せず、その旨を `RESULTS.md` に記録して穏当に終了する。
